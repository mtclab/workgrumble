# Terminal fidelity: one row per command

Standing bar, added in `docs/SPEC_020.md`. Every command this terminal admits to having
declares a TIER, and no new command ships without a row here.

- **FAITHFUL** - real syntax, real flags, real output shape, real error wording. A player who
  knows the tool recognises it and learns nothing false.
- **SHAPED** - the right concept and the right shape over smaller data, or over data this
  world has and the real one does not. Nothing in it is false; some of it is missing, and
  what is missing is written in the omissions column.
- **REFUSED HONESTLY** - answers the way a real shell answers something it cannot do, or says
  plainly that it is not simulated. A refusal teaches nothing; a fake teaches something wrong.

The house rules that apply to every row:

- **Families are not one shell in hats.** This estate is a Windows-family parody, so the
  spelling is `cmd`/`sc`/`net`, not `systemctl`. The unix skins arrive with the machines that
  would run them, and they will differ in output shape rather than in spelling.
- **No invented state.** Where a column would need a fact the world does not hold - a
  binary path, a service account, a dependency list - the column is left out rather than
  filled in. An omission is a gap; an invention is a lie the player learns.
- **The world is the only source.** Everything printed is read from the graph or derived by a
  pure function of it (`cmd-net.ts` derives every address). Nothing is a string in a switch.

## The unix half of the filesystem slice, and why it is not here

`SPEC_020` 0.2.3 lists `ls`, `cd`, `pwd`, `cat` and `less` beside the four above. They are
NOT shipped, and the reason is the first house rule on this page: families are not one shell
in hats. There is no Linux skin in this estate - every box in the building is a Windows-family
box, from `services.msc` down to the `Netlogon` on every workstation - so a `ls` would be a
unix spelling over a cmd-shaped world, printing this world's columns under another family's
name. That is the exact failure the bar exists to forbid, and it is worse than the absence:
the absence teaches nothing, and half a dialect teaches something wrong.

They arrive with the machines that would run them, and when they do they have to differ in
OUTPUT SHAPE rather than in spelling: `dir` prints a volume header, a date-and-size column
and a free-space footer; `ls` prints columns and nothing else, and `cd` on its own takes a
unix shell home rather than printing where it is.

## The mac dialect (0.33.0), and the audit of the shared unix table

The third family got its session in 0.33.0: `ssh` to a Mac opens a zsh prompt at the Engineer
tier, where 0.32.0 refused by name. A third dialect is not a third command set - it is an
AUDIT of the second one, the way `machineOs: 'mac'` was an audit of every `=== linux` check -
because every shared verb on this box was written against Ubuntu and half of them say so.

Two house rules run this section, on top of the three at the top of the page:

- **A refusal says what is true of the box in front of you.** `zsh: command not found:
  systemctl` is the truth about a Mac. The same sentence about `open` would be a lie - `open`
  is on every Mac ever shipped - so a real tool this terminal does not model says exactly
  that, and says what the tool is for.
- **Fix the output source, do not fork the command.** `df` is one command with a family-aware
  table, not two `df`s. Where a shared verb needed a mac answer, the answer moved into the
  renderer; nothing was duplicated.

### The audit of the shared table: carried, fixed, or refused

| Verb | On a Mac | Why |
| --- | --- | --- |
| `ls`, `chmod`, `chown`, `whoami`, `curl`, `dig`, `host` | CARRIED | POSIX or BSD-identical for what this dialect prints. `ls -la`'s columns are the same columns; `dig` and `host` are on macOS (bind tools ship in the base system through Sequoia); `curl` is Apple's own. |
| `df` | FIXED | Two different tables. BSD heads the column `Capacity` and adds `iused`/`ifree`/`%iused`; GNU heads it `Use%` and prints no inodes. The device is the other tell: `/dev/root` on Linux, a synthetic APFS snapshot (`/dev/disk3s1s1`) at `/` on a Mac. A Mac's Size is derived from its own seeded free space rounded up to a real disk, because a designer's 320G of project files cannot live on the Linux server's 40G root. Inode counts are DERIVED (the estate holds no inode table) the way `ps`'s VSZ and `tracert`'s hop times are, and `ifree` is APFS's own constant. |
| `du` | FIXED | The directories are the box's, not a server's. No `/var/log/journal`, because there is no journald; the home is under `/Users`; what is eating a designer's disk is the Caches/Application Support/Movies trio and `/Applications`. An empty directory reads `0B` (APFS) rather than `4K` (ext4). |
| `ps aux` | FIXED | PID 1 is `/sbin/launchd`, not `/sbin/init` - the sharpest one-line family difference there is. BSD heads the columns `TT` and `STARTED` where procps heads them `TTY` and `START`. Who a job runs as is READ off the domain: a `system` job is root, a `gui/501` job is the logged-in user. OMITTED: a real `ps` prints the executable and the world holds a launchd LABEL rather than a program path, so the COMMAND cell carries the label - a true thing in a column that would hold a path, rather than an invented `/usr/sbin/` for somebody else's daemon. |
| `ping` | FIXED | Continuous on both families, and different in every detail around it: BSD announces `56 data bytes` where GNU announces `56(84) bytes of data`, BSD's `icmp_seq` starts at 0, the summary says `packets received` and `round-trip min/avg/max/stddev` rather than `received` and `rtt ... mdev`, no elapsed time, and an unresolvable name is `cannot resolve x: Unknown host`. |
| `ifconfig` | FIXED, and NOT GAGGED | On Ubuntu this is a not-installed gag pointing at `ip`; on a Mac it is the base system and the canonical tool, so it runs with no package and no hint. `en0`, not `eth0`; loopback listed first; the netmask in HEX (`0xffffff00`), which is the single most disorienting thing about reading a Mac's addresses; media and status lines rather than net-tools' RX/TX counters. |
| `netstat` | FIXED, and NOT GAGGED | BSD's table: addresses written `host.PORT` with a dot, the state column headed `(state)`, `tcp4` as the proto. NO process column, because `-p` on BSD selects a PROTOCOL (`netstat -p tcp`) and has nothing to do with processes - a bare `-p` is answered with that and pointed at `lsof -i`, which is where the owning process really comes from. |
| `traceroute` | FIXED, and NOT GAGGED | Base system on macOS. The defaults are the tell: 64 hops max and 52-byte probes on BSD, 30 and 60 on Linux. |
| `htop` | REFUSED HONESTLY | Genuinely not on macOS, and the way onto a Mac is genuinely Homebrew, which is genuinely not on a managed fleet box - so the miss says the whole chain and names `top` and Activity Monitor, which are what ship. |
| `id` | FIXED | uid 501, not 1000; primary group `staff` (gid 20), not a group of the user's own name; root's group is `wheel`, which is where the old "add them to wheel" instruction comes from; the supplementary list is a local admin's real one. OMITTED: the ninety-odd `_`-prefixed system accounts (`_www`, `_spotlight`) - the world holds none, they are derived from nothing it does hold, and ninety invented accounts would be the largest fabrication in the dialect. |
| `systemctl`, `journalctl` | REFUSED BY NAME | launchd is not systemd. The refusal names `launchctl` with a domain target and `log show`. |
| `apt`, `dnf`, `yum`, `zypper`, `pacman`, `dpkg`, `subscription-manager` | REFUSED BY NAME | macOS has no system package manager at all, and no package database - what is installed is applications and receipts, which is a different model rather than a different spelling. |
| `getenforce`, `sestatus`, `restorecon`, `setenforce` | REFUSED BY NAME | SELinux is a Linux kernel module. macOS confines processes with its sandbox, SIP and TCC - different mechanisms, no contexts on files. |
| `ip`, `ss` | REFUSED BY NAME | iproute2 is Linux's. The refusals name `ifconfig` and `netstat -an`/`lsof -i`, which are here and are not deprecated on this family. |
| `getent` | REFUSED BY NAME | glibc's NSS front end. macOS keeps accounts in Directory Services and reads them with `dscl`, which is not simulated and says so. |
| `certbot` | REFUSED BY NAME | Not on this box. Nothing on a designer's Mac terminates TLS; the certificates this shop renews are on the Linux servers. |
| `changereq`, `breakglass`, `postmortem` | CARRIED, sentence FIXED | Process rather than operating system, so they exist on both families. The one leak was the miss: `Unit nginx.service could not be found` is a systemd unit name, and a Mac says `No job labelled "x" is loaded on this box.` |
| `exit`, `logout` | CARRIED | Same verb, same session, same way out. |

| `launchctl bootstrap <domain> <plist>` | `launchctl bootstrap system /Library/LaunchDaemons/x.plist` | nothing, on success | SHAPED | The asymmetry is REAL and is the thing people get wrong: `bootout` takes a target and `bootstrap` cannot, because the job is not in the domain yet and there is nothing to name - it takes the domain and a PATH. A target handed to it is refused with that sentence rather than quietly accepted. A path the box has no plist at answers `Bootstrap failed: 5: Input/output error`, which is what the real one says, with a plain-language line under it. |
| `launchctl load` / `unload` | the legacy pair | - | REFUSED HONESTLY | Named and refused. They are the vocabulary most instructions on the web still use, they take a plist and no domain, and shipping half a vocabulary is the failure this page exists to forbid. The refusal lists the five modern verbs. |
| `log show [--last <n>]` | `log show --last 1h` | `Timestamp / Thread / Type / Activity / PID / TTL`, a rule, then `Log - Default: N, Info: 0, Debug: 0, Error: 0, Fault: 0` | SHAPED | The Mac's face of a log this world already holds: the SAME lines `journalctl` reads off the jobs on the box - one log, two faces, the spool-directory rule, no second store to keep true. NOT the Windows `event_log` field, and that is a ruling: those rows are Windows sources (Service Control Manager, Print, the Security log) and a Console face over them would be naming Windows subsystems on a Mac, which is the lie the 0.32.0 audit exists to kill. `--last` is the real flag and is NOT applied - the lines this world holds carry no machine-readable timestamp to filter on - and the output says so on its last line rather than letting a player believe a window ran. `log stream` is refused: it runs until interrupted and this terminal cannot interrupt anything. |
| `brew` | `brew install <formula>` | `zsh: command not found: brew` on a box without it | REFUSED HONESTLY | Homebrew is not part of macOS. It is a third-party manager somebody installs by hand under `/opt/homebrew`, and these desks are MDM-enrolled: their software comes from the management catalogue, which is what "managed fleet" means. A simulated `brew install` would have been a fabricated package manager on a box that has none - a bigger lie than the absence, and one that teaches exactly the wrong instinct about a managed fleet. |
| `open`, `pbcopy`, `pbpaste`, `softwareupdate`, `dscl`, `networksetup`, `scutil`, `defaults`, `diskutil`, `sw_vers` | real macOS tools | - | REFUSED HONESTLY | Not "command not found", because that would be a lie about a binary every Mac has. Each says the tool IS on this box, that this terminal does not simulate it, and what it does - so the miss still teaches. A `softwareupdate --list` that invented three updates would be teaching a player this box's patch state, which the world does not hold. |

## What the drive is, underneath these four

One paragraph, because every row above leans on it. Directories and files are nodes in the
same graph as everything else, joined by `contains` edges, and a listing is READ from it -
there is no second tree anywhere to keep true. Two entries are read from somewhere else in
the world rather than from a `content` field, and both are derived by a pure function of a
field another surface already paints:

- the spool directory on a print server IS the queue on the printer plugged into it, so what
  `dir` shows and what `queue` reports cannot come apart. The world holds one line per job -
  a size and a minute, nothing more, because that is what a listing prints - and the
  agreement between that list and the queue length is asserted after every mutation that
  touches either, including after every step of every advertised path in the solvability
  harness;
- `C:\WINDOWS\SYSTEM32\LOGFILES\SYSTEM.LOG` IS the machine's own event log, off the field the
  Event Viewer paints, so the file and the window are two views of one truth. Both windows now
  date a line the same way - `09/09/1998  16:56` - because a log line and a directory listing
  describing the same evening had no business making the player convert "Day 3" into a date.

There is a third directory whose listing is read rather than walked, and it is not derived from
another surface: a directory a PROGRAM fills. The world holds one line per file - a name, a size
and a minute - and holds nothing else, for the same reason the queue does: a file's size on these
drives is what `type` would print, so a directory of text files can never be a directory that has
eaten a drive, and a drive eaten by one directory is a real fault whose diagnosis is a listing's
own byte total held against the free space in its own footer. `type` on one of those files refuses
in the shape the spool refusal has, and for the same true reason - the world knows how big it is
and when it was written, and nothing else. The byte total the drive believes in is a second field
beside the list, exactly as `queue_len` sits beside `spool_jobs`, and `storedDisagreements` is the
gate that keeps the two in step after every mutation that touches either.

Reaching another box is `\\HOST\C$`, the administrative share, which works here for the
reason it works in the trade: the Server service is running on every box in this building and
the player can see that it is in any services list. It is a different mechanism from the
Remote Registry that `tasklist /s` is refused for, which is Disabled everywhere - and that
difference is the point.
